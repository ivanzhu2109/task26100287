# collabdoc — 协作文档离线合并内核

Go 库，由上层直接调用。正文与编辑历史只存内存。基于 RGA 风格 CRDT：
每个字符有全局唯一 ID，删除是墓碑标记，插入记录引用"插在哪个字符之后"，
副本之间只交换不可变编辑记录，无需中央排序或全量重传。

## 特性

- 最多 10 名作者（编号 0–9），每人只在一个副本上产生编辑。
- 四种操作：按位置插入文本、删除连续区间（左闭右开）、接收编辑记录、读取正文。
  位置一律按 Unicode 码点计数。
- 记录可乱序、重复到达；因果依赖（版本向量）未齐的记录进入等待队列，
  依赖补齐后自动生效；重复记录不产生任何效果。
- 删除只作用于生成记录时实际看见并选中的字符（按字符 ID），
  并发插入在删除区间内部或边界的字符保留，迟到记录不会复活已删除字符。
- 同一缝隙（同一对具体字符之间，含文首文尾）的并发插入按作者编号升序排列，
  同作者后到的插入靠左；并发整段插入不会互相穿插。
- 已生效记录集合相同的任意两个副本，读取结果逐码点一致，
  与到达顺序、重复次数无关。

## API

```go
doc := collabdoc.New(author uint8, initial string) // author ∈ [0,10)
rec := doc.Insert(pos int, text string)            // 本地插入，返回可分发记录
rec  = doc.Delete(start, end int)                  // 本地删除 [start,end)，返回记录
doc.Receive(rec)                                   // 接收其他副本的记录
text := doc.Read()                                 // 读取当前正文
n    := doc.Len()                                  // 当前正文码点数
```

同一副本上的调用需串行执行；不提供持久化、崩溃恢复与历史版本查询。

## 实现要点

- 字符存于隐式 treap（中序即线性顺序），聚合子树大小、可见字符数、
  最小 RGA 深度，插入/删除/定位均为期望 O(log n)。
- 初始正文以 O(n) 笛卡尔树构建。
- 远程插入通过"跳过排序在前的兄弟及其整棵子树"定位，兄弟排序规则为
  （作者编号升序，字符序号降序），保证所有副本得到唯一的线性顺序。
- 因果依赖用版本向量 `[10]uint32` 判定；等待队列在每次接收后自动排空。

## 运行测试

```sh
go test ./...        # 全部测试（含规模资源测试，约几秒）
go test -short ./... # 跳过规模资源测试
go test -v -run TestResourceScale .   # 只跑规模资源测试
```

测试覆盖：

- `TestAcceptanceConcurrentRuns`：验收场景 1（"ab" + 并发"甲乙"/"XY" + 段内"!"，
  含重复与因果缺口），结果 `a甲!乙XYb`，缺依赖时不提前显示 "!"。
- `TestAcceptanceDeleteVsConcurrentInsert`：验收场景 2（删除 [1,3) 与并发插入 "Z"），
  结果 `aZd`，重复删除不删 "Z"。
- `TestTenAuthorsConvergence` / `TestSameAppliedSetSameText`：10 名作者多轮分支编辑，
  含中文、补充平面字符与组合字符；已生效记录集合相同的观察点逐码点一致。
- `TestResourceScale`：累计规模上限（初始 50 万码点、共 100 万码点文本、
  7000 条唯一记录、删除选中累计 200 万码点、每条记录投递 3 次）。
  实测（Apple Silicon）：接收全部记录并读出最终正文约 0.5 秒（限 30 秒），
  单副本驻留堆内存约 105 MiB（限 512 MiB）。
