# docmerge — 协作文档离线合并内核

Go 库，由上层直接调用；正文与编辑历史只存内存。基于 RGA 风格 CRDT：
副本间只交换不可变编辑记录，无需中央排序或全量重传。

## API

```go
r := docmerge.NewReplica("初始正文", 0) // 作者编号 0..9，所有副本初始正文相同
rec1 := r.Insert(pos, "文本")          // 按码点计的位置插入，立即可见
rec2 := r.Delete(start, end)           // 删除左闭右开区间 [start, end)
r.Receive(rec)                         // 接收其他副本的记录（可乱序、可重复）
s := r.Text()                          // 读取正文
n := r.Len()                           // 正文码点长度
```

`Record` 是不可变值，可直接转交给其他副本；`Receive` 返回时，
所有已收到且依赖齐全的记录都已生效。

## 运行测试

```sh
go test ./...        # 全部测试
go test -v ./...     # 查看规模测试的耗时与内存数据
go test -race ./...  # 竞态检查（可选）
```

测试覆盖：

- `TestConcurrentRunsAndCausalGap`：验收用例 1——`ab` 上并发插入
  `甲乙`/`XY` 与后续 `!`，含重复投递与因果缺口，收敛为 `a甲!乙XYb`，
  缺依赖时不提前显示 `!`。
- `TestDeleteSkipsConcurrentInsert`：验收用例 2——删除 `[1,3)` 与并发
  插入 `Z` 并存为 `aZd`，重复删除不删 `Z`。
- `TestTenAuthorsConvergence`：10 名作者多轮分支编辑，含中文、补充平面
  （𝄞、😀）与组合字符（e◌́）；在已生效记录集合相同的每个观察点，
  各副本正文逐码点一致；整体重复投递不产生新效果。
- `TestResourceLimits`：累计规模上限（初始 50 万码点、9992 条唯一编辑、
  插入累计 100 万码点、删除区间累计约 200 万码点、每记录投递 3 次），
  单副本接收全部记录并读出最终正文。参考数据（M 系列 Mac）：
  约 0.2 秒、堆内存约 120 MiB，远低于 30 秒 / 512 MiB 的限制。

## 设计要点

- 字符序列用带父指针的 treap 维护，中序即文档顺序；子树维护可见计数，
  支持 O(log n) 的按码点定位；删除为墓碑标记，重复删除幂等。
- 每个字符有全局 ID（作者, 序号）；初始正文作者为 -1，文首有哨兵。
  插入记录携带左邻字符 ID；同一左邻下的兄弟块排序键为：
  非初始块先于初始正文字符，非初始块之间按（作者升序，字符序号降序）。
  因此同一缝隙的并发插入按作者编号升序，整段不交错，且“在字符 b 前
  插入”的本地语义得以保留。
- 每条记录携带版本向量（生成时已看见的各作者记录数）。依赖未齐的记录
  进入缓冲；每次 `Receive` 后循环冲刷，直到没有可生效记录为止。
- 删除记录列出生成时实际选中字符的 ID 区间，只标记这些字符；
  并发插入在删除区间内部或边界的字符不受影响，迟到记录不会复活已删字符。
